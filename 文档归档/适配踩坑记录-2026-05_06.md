## 早期环境问题

### Gradle Wrapper 本地路径反复被恢复

**现象**: 每次 commit 前手动把 `gradle-wrapper.properties` 改为本地文件路径，但用户 git 操作时会被恢复为 HTTPS URL，导致下次编译时又去下载 Gradle。

**解决**: 每次编译前检查并改回本地路径，编译完再恢复为 HTTPS URL。

```properties
# 编译用（本地）
distributionUrl=file:///home/liu/Documents/legado-master/.gradle/gradle-8.13-bin.zip
# 提交用（恢复原样）
distributionUrl=https\://services.gradle.org/distributions/gradle-8.13-bin.zip
```

### 代理设置不生效

**现象**: `http_proxy` 环境变量设置了，但 Gradle Wrapper 下载时仍报 `Connection timed out`。

**原因**: Gradle Wrapper 用 Java 自己的网络栈，不一定读取 shell 环境变量。

**解决**: 将 Gradle zip 包放到本地 `.gradle/` 目录，使用 `file:///` URL 引用，彻底绕过下载。

## 构建 Release APK 注意事项

### Gradle Wrapper 本地路径切换

每次构建前必须确认 wrapper URL。项目没有全局 Gradle 时依赖 `.gradle/gradle-8.13-bin.zip`：

```properties
# 构建前（临时改为本地路径）
distributionUrl=file:///home/liu/Documents/legado-master/.gradle/gradle-8.13-bin.zip

# 构建完（恢复原样，避免误提交）
distributionUrl=https\://services.gradle.org/distributions/gradle-8.13-bin.zip
```

### Release 签名配置

签名信息存储在 `app/gradle.properties`，不会提交到 git：

```properties
RELEASE_STORE_FILE=signing/legado-self-release.jks
RELEASE_STORE_PASSWORD=********
RELEASE_KEY_ALIAS=legado-self
RELEASE_KEY_PASSWORD=********
```

Keystore 位置: `app/signing/legado-self-release.jks`。`app/signing/` 和 `app/gradle.properties` 已加入 `.gitignore`，但 keystore 和密码必须本地备份。

### 构建产物位置

```text
app/build/outputs/apk/app/release/
├── legado_arm64.apk
├── legado_all.apk
├── legado_x64.apk

```

### Release 构建耗时

- 首次构建约 15-20 分钟。
- 后续构建约 3-5 分钟。
- 关键耗时阶段: `:app:minifyAppReleaseWithR8`。

### Kotlin 2.2 / AGP 9 下 release Kotlin 编译 warning 清理

**记录日期**: 2026-06-06  
**验证环境**: Kotlin 2.2.21, AGP 9.2.1, Gradle 9.4.1, targetSdk=36, compileSdk=36, minSdk=26  
**验证命令**: `./gradlew :modules:rhino:compileReleaseKotlin :app:compileAppReleaseKotlin --no-daemon --warning-mode all --rerun-tasks`

**处理原则**:
- 可空性警告优先改代码表达真实类型，不用工程级 suppress。
- AndroidX/Rhino 上游兼容 API 暂不大迁移，使用文件或调用点局部 `@Suppress("DEPRECATION")`。
- 系统 UI 旧 flag 仅在兼容封装或阅读页沉浸逻辑中局部压制。
- Kotlin 注解目标警告用显式 use-site target，例如 `@param:DrawableRes`。
- `GlobalScope` 只有跨 Activity/Service 生命周期的延迟结算任务可局部 `@OptIn(DelicateCoroutinesApi::class)`。
- 被成员方法遮蔽的扩展函数应删除，并移除多余 import。

**已验证**: 2026-06-06 强制重跑 release Kotlin 编译通过，未再输出 Kotlin warning。

## 前台服务启动入口统一（2026-06-01）

### 背景

Android 8+、12+、14+ 对后台启动前台服务限制越来越严。朗读、音频播放、缓存、导出、Web 服务依赖 Service，入口走普通 `startService()` 容易出现偶发启动失败或被系统拒绝。

### 改法

- `ContextExtensions.kt`: `startForegroundServiceCompat()` 直接调用 `ContextCompat.startForegroundService()`；新增 `safeStartForegroundService()` 捕获异常并写 AppLog + toast。
- 启动类入口改用前台启动：朗读、音频播放、缓存、检查书源、下载、导出、WebService。
- 运行中 action 保留普通 `startService()`，但先判断对应服务 `isRun`。
- `CheckSourceService` 新增 `isRun` 标志，在 `onStartCommand` 设为 true，`onDestroy` 设为 false。

### 核心原则

- 启动前台服务 → `ContextCompat.startForegroundService()`。
- 给已运行服务发命令 → 普通 `startService()`，并先判断 `isRun`。
- 不要机械替换所有 `startService()`，否则 stop/pause 可能反而启动新服务。

### 16. WebDAV 恢复备份后 SAF 授权路径不一致导致本地书卡加载中并反复拉进度

> 归档自 `../适配踩坑记录.md`（2026-06-26 归档，因新增 API 37 适配条目，按 15 条上限移出最旧一条）。

**记录日期**: 2026-06-14  
**验证环境**: MI PAD 4, Android 8.1；targetSdk=36, compileSdk=36, minSdk=26  
**文件**: `BaseReadViewModel.kt`, `ReadBookViewModel.kt`, `AppWebDav.kt`, `RemoteBookViewModel.kt`

**现象**:
- 老设备从 WebDAV 恢复新设备备份后，打开本地书《我有一座恐怖屋》。
- 日志在 11:47:18 抛 `SecurityException: Permission Denial`，URI 形如 `content://.../tree/primary:yuedu/...epub`。
- 阅读页一直卡在“加载中”，随后多次打开 `ReadBookActivity`，并多次拉取 WebDAV 进度 `chapter=840 pos=205`。
- 老设备实际可重新授权的目录是 `primary:阅读`，SAF 树路径目录名与新设备不同。

**根因**:
- WebDAV 备份恢复的是完整数据库，书籍 `bookUrl` 仍指向新设备授权目录 `primary:yuedu`。老设备 SAF 授权丢失且路径不一致，读取时抛 `SecurityException`。
- `BaseReadViewModel.loadChapterList()` 本地书异常路径只 `postValue(emptyList())`，没有回调 `onLocalBookLoadError()`，导致阅读页错误状态收口不完整。
- `ReadBookViewModel.initBook()` 在章节列表为空/本地文件不可读时虽然 return，但 `ReadBook.initData()` 提前触发页面刷新，`ReadBook.msg` 尚未设置为错误文案，页面先进入“加载中”占位。
- `AppWebDav.downloadAllBookProgress()` 对本地书未做可读性校验，也未校验远端 `durChapterIndex` 是否在当前书籍章节数范围内，直接把远端进度写入不可读/章节不匹配的本地书记录。
- 远程书籍入口已具备“同名本地书不可读则重新导入”逻辑，但 401 下载失败与本地 `SecurityException` 混在一起记录，不利于区分服务端鉴权问题。

**修复**:
- `BaseReadViewModel.loadChapterList()` 本地书 catch 块保留空章节结果以阻止后续加载，同时调用 `onLocalBookLoadError(book, e)`。
- `ReadBookViewModel.initBook()` 对本地书先执行 `checkLocalBookFileExist()`，失败时立即 `isInitFinish = true` 并 return，确保 `ReadBook.msg` 已是错误文案，不进入“加载中”。
- 本地书章节列表为空时，设置“目录为空或无法加载”错误文案并触发目录重选。
- `AppWebDav.downloadAllBookProgress()` 写入进度前校验：所有书检查远端 `durChapterIndex` 是否落在 `0 until simulatedTotalChapterNum()`；本地书额外检查文件可读，否则跳过并记录明确日志。
- `RemoteBookViewModel.readOrImport()` / `addToBookshelf()` 错误处理区分 `WebDavException` 且消息含 `401` 的情况，单独记录“WebDAV 认证失败(401)”。
- **后续修复 (2026-06-16)**: WebDAV 在线恢复新增“仅恢复阅读进度”模式。该模式只读取 `bookProgress/*.json`，按当前设备已有书籍的 `name + author` 匹配，写入 `durChapterIndex`、`durChapterPos`、`durChapterTitle`、`durChapterTime`、`syncTime`，不下载备份 zip、不恢复 `bookshelf.json`，避免跨设备写入失效 `content://.../tree/...`。

**回归点**:
- 从 WebDAV 恢复备份后，若本地书 URI 授权丢失或目录不一致，打开该书应提示“打开本地书籍出错，请选择书籍所在文件夹”，并弹出目录选择器。
- 重新选择正确目录后应能加载目录和正文；不重新选择则不应卡“加载中”。
- 远端进度索引超过本地章节总数时，`downloadAllBookProgress` 应跳过并打日志，不写入数据库。
- 本地书不可读时，`downloadAllBookProgress` 应跳过该书，不写入任何进度。
- WebDAV 远程书籍下载返回 401 时，日志应明确标记“WebDAV 认证失败(401)”。
- Android 16 设备备份、Android 8.1 设备恢复时，选择“仅恢复阅读进度”不应修改本地书 `bookUrl`，也不应出现 `primary:yuedu` 的 Permission Denial。
- 未导入同名同作者本地书时，“仅恢复阅读进度”应跳过远端进度，不创建旧路径本地书。

### 14. WebDAV 日志必须带上下文且避免敏感信息

> 归档自 `../适配踩坑记录.md`（2026-06-26 归档，因新增 API 37 适配条目，按 15 条上限移出最旧条目）。

**记录日期**: 2026-06-06
**验证环境**: Gradle 9.4.1 + AGP 9.2.1；`scripts/check-debug.sh` 编译通过
**文件**: `AppWebDav.kt`, `WebDav.kt`

**目标**:
- WebDAV 配置、认证、上传/下载阅读进度和全量同步失败时，日志能看出操作类型、路径阶段、HTTP 状态或进度文件名。
- 日志不能记录 WebDAV 账号、密码、Authorization header、URL query 和 fragment。

**实现**:
- `WebDav.safeLogUrl()` 统一脱敏 URL：移除 userinfo、query、fragment。
- `WebDav.check()` 和 `checkResult()` 输出脱敏 URL，认证失败仍保留 HTTP code / is401。
- `AppWebDav.upConfig()` 增加配置版本、server/root URL（脱敏）和过期配置日志。
- `uploadBookProgress()` / `getBookProgress()` 日志增加进度文件名、章节 index 和 pos；成功和跳过原因走 `AppLog.putDebug()`，失败走 `AppLog.put()`。
- `downloadAllBookProgress()` 增加远端进度文件数、匹配数、更新数，并捕获异常写入 WebDAV 上下文。

**维护注意**:
- 新增 WebDAV 日志时不要拼接 `Authorization.toString()`。
- 高频成功日志优先用 `AppLog.putDebug()`。

### 15. 本地 EPUB 读取权限丢失后阅读页卡“加载中”

> 归档自 `../适配踩坑记录.md`（2026-06-26 归档，因新增 API 37 适配条目，按 15 条上限移出最旧条目）。

**记录日期**: 2026-06-08
**验证环境**: vivo V2458A, Android 16, WebView 148；targetSdk=36, compileSdk=36, minSdk=26
**文件**: `BaseReadViewModel.kt`, `ReadBookViewModel.kt`, `RemoteBookActivity.kt`, `RemoteBookViewModel.kt`

**现象**:
- 打开本地 EPUB 时，阅读页一直显示“加载中”。
- 日志中先出现 `SecurityException: Permission Denial`，路径为 `content://com.android.externalstorage.documents/tree/...epub`。
- 同一轮操作里 WebDAV 进度文件请求返回 200；另有远程 EPUB 下载请求返回 401，需要单独排查服务端鉴权/路径规则。

**根因**:
- 本地书 `loadBookInfo()` 会先调用 `FileBook.upBookInfo(book)` 读取 EPUB 元信息/封面。
- SAF 目录授权丢失或书籍目录不匹配时，`ContentResolver.openInputStream/openFileDescriptor` 抛 `SecurityException`。
- 旧逻辑只在 `initBook()` 后面的 `checkLocalBookFileExist()` 和目录加载阶段处理权限失败；更早的书籍信息加载异常会走通用失败路径，阅读页 loading 状态收口不明确。
- “远程书籍”列表点击已在书架的非压缩包书籍时，旧逻辑只按文件名查本地书并直接打开，没有先验证本地 `bookUrl` 是否仍可读。

**修复**:
- `BaseReadViewModel.loadBookInfo()` 的本地书分支增加 `try/catch`，失败时设置 `curBook`、发布空章节列表并回调子类。
- `ReadBookViewModel.onLocalBookLoadError()` 将页面消息改为“打开本地书籍出错”，并在 `SecurityException` / `FileNotFoundException` 时触发 `permissionDenialLiveData`，引导用户重新选择书籍所在文件夹。
- `RemoteBookActivity.startRead()` 改为委托 `RemoteBookViewModel.readOrImport()`。远程书籍入口发现同名本地书时先验证可读；不可读时使用当前远程条目重新导入/下载。

**回归点**:
- 手动撤销/变更书籍目录授权后打开本地 EPUB，应提示重选目录，不应一直显示“加载中”。
- 重新选择正确目录后，应能重新加载目录和正文。
- WebDAV 远程书籍列表中，已在书架但本地 URI 失效的普通 EPUB/TXT，点击后应尝试重新下载。
