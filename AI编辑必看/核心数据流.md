# AI 编辑必看 - 核心数据流

> 返回主入口: `../AI编辑必看架构图.md`

---

## 阅读器数据流

```text
ReadBookActivity
└── ReadBookViewModel.initData(intent)
    ├── 从 Intent/数据库拿 Book
    ├── BaseReadViewModel.upBook()
    │   ├── 本地书: FileBook.upBookInfo() / FileBook.getChapterList()
    │   └── 在线书: WebBook.getBookInfoAwait() / getChapterListAwait()
    └── ReadBook.initData(book)
        ├── 设置当前书、章节数、进度、ContentProcessor
        ├── ReadBook.loadContent()
        └── ChapterProvider.getTextChapterAsync() -> TextChapter -> TextChapterLayout 分页 -> ReadView 绘制
```

高风险点:

- `chapterList` 可能为空，访问第一个元素必须用 `firstOrNull()`。
- 本地 EPUB/SAF URI 可能在备份恢复或目录授权变化后失效，必须收口 loading 并提示重选目录。
- WebDAV 进度写入前必须校验章节范围；仅同步/恢复进度使用 `RangeOnly`，不检查本地 SAF 可读性，真正加载本地书内容时才使用 `ReadableRequired`。

## WebDAV 数据流

```text
AppWebDav.upConfig()
├── 校验 server/root URL
├── 初始化 bookProgress/books/background 目录
└── 设置 authorization/defaultBookWebDav

进度同步
├── 上传: AppWebDav.uploadBookProgress() -> bookProgress/*.json
└── 下载: AppWebDav.getBookProgress() / downloadAllBookProgress()

Web 阅读进度
├── 打开书架: 只读 Room，不触发 WebDAV
├── 点击书籍: POST /syncBookProgress -> 单书拉取 -> 只应用更靠前且范围有效的远端进度
├── 连续阅读: 浏览器固定 5 秒窗口 -> POST /saveBookProgress -> 先写 Room
├── WebDAV 上传: WebBookProgressUploadScheduler 固定 60 秒窗口，只上传最新 dirty 位置
└── 切章/隐藏/离开: /saveBookProgress?flush=true；关闭页面用同一路径的 Beacon
```

规则:

- 不记录账号、密码、Authorization、URL query/fragment。
- 401 是服务端鉴权/路径问题，要和本地 `SecurityException` 分开记录。
- 恢复备份后的 `content://.../tree/...` 不能跨设备假设有效。
- Web 单书拉取、App 启动全量拉取和 Web 上传按书互斥；远端落后时不得覆盖 Room。
- 进度去重键不含时间戳；上传失败后不循环重试，只等待新位置、离开页面或重新打开书籍。

## Web 前端资源边界

- `modules/web/src/` 是源码，`app/src/main/assets/web/` 是 APK 内实际加载内容。
- 修改 Web 运行时源码后，必须同步 assets，否则打包后不生效。
- 阅读页核心文件通常是 `modules/web/src/views/BookChapter.vue` 和 `modules/web/src/store/bookStore.ts`。
- 无限滚动追加章节不要走全局 loading mask。
