> 返回主入口: `../AI编辑必看架构图.md`

## 阅读器数据流

```text
ReadBookActivity
└── ReadBookViewModel.initData(intent)
    ├── 从 Intent/数据库拿 Book
    ├── BaseReadViewModel.upBook()
    │   ├── 本地书: FileBook.upBookInfo() / FileBook.getChapterList()
    │   └── 在线书: WebBook.getBookInfoAwait() / getChapterListAwait()
    └── ReadBook.initData(book)
        ├── 设置当前书、章节数、进度、ContentProcessor
        ├── ReadBook.loadContent()
        └── ChapterProvider.getTextChapterAsync() -> TextChapter -> TextChapterLayout 分页 -> ReadView 绘制
```

高风险点:

- `chapterList` 可能为空，访问第一个元素必须用 `firstOrNull()`。
- 本地 EPUB/SAF URI 可能在备份恢复或目录授权变化后失效，必须收口 loading 并提示重选目录。
- 阅读尺寸变化（2026-09-06）: `ContentTextView.onSizeChanged()` → latest-wins 尺寸协调器 → `ChapterProvider` 更新可见区与 `sizeGeneration` → `ReadBook.onPageSizeChanged()` 取消并清除前/中/后章节分页；Activity 已初始化则立即重载，未初始化则由初始化后的 `loadOrUpContent()` 加载。不能仅发送可能被初始化门槛忽略的配置事件。
- `processContent()` 的内容处理仍在 IO；只在 Main 构造 `TextChapterLayout` 的尺寸快照，排版工作使用外层加载作用域继续在 IO 执行。分页结果挂载前在 Main 校验尺寸代次，await 入口必须先校验、再取消旧章节；过期分页抛出取消，不得吞掉后误报成功。重新打开同一本书也不能复用旧尺寸的已完成分页。
- WebDAV 进度写入前必须校验章节范围；仅同步/恢复进度使用 `RangeOnly`，不检查本地 SAF 可读性，真正加载本地书内容时才使用 `ReadableRequired`。

## 外部文件关联导入

```text
AssociationActivity / FileAssociationDialog
└── FileAssociationViewModel.dispatchIntent()
    ├── 已知二进制书籍格式直接进入本地书导入
    └── JSON 或小型 TXT 先做内容类型探测
        └── LocalBookFileImportHelper
            ├── 全局互斥事务内查找或创建目标
            ├── 源文件暂存并计算大小/SHA-256
            ├── 旧目标备份并校验
            ├── 覆盖目标并重新校验
            └── 失败或取消时在 NonCancellable 中回滚并校验
                └── FileBook.importLocalFile()
                    ├── 流式计算内容 SHA-1
                    ├── LocalBookIdentity 生成 SHA1(文件 URI + 内容 SHA1)
                    ├── 优先按 localFileKey，再按精确 bookUrl 匹配已有记录
                    └── Room 插入新书或更新同一文件
                        ├── style1/style2 书架按 bookUrl 区分 Diff 条目
                        └── 后续换路径走 BookDao.relocate() 事务
```

规则:

- 不同 Provider Uri 可能指向同一底层文件；只有只读文件描述符确认 `st_dev/st_ino` 相同时才能跳过复制。
- 禁止直接执行“源流 → 已存在目标的 `wt` 流”；目标创建状态、备份、覆盖、校验和回滚必须处于同一互斥事务。
- 临时文件必须使用系统唯一文件名；新目标失败时删除，旧目标回滚后必须核对原备份的大小和 SHA-256。
- 用户取消后先完成回滚和临时文件清理，再关闭文件关联界面或进入其他终态。
- 书名、作者和文件名只用于展示/检索，不得作为本地书唯一键。不同 URI 各自建书，即使内容相同也不合并；同一 URI 的文件被原地覆盖后，重新导入更新该 URI 对应的记录及内容摘要。
- 83 及更旧数据库升级后，旧本地书的 `localFileKey` 允许为空，不在迁移期间从 SAF 读取文件；下次重新导入时再补齐。
- 变更已持久化书籍的 `bookUrl` 必须在 Room 事务内写入目标行、删除旧行并清理过期 `localFileKey`；不得再依赖书名+作者冲突的 `REPLACE` 副作用。
- `Book` 行、章节和行内阅读位置按 `bookUrl` 分开；WebDAV 进度用独立的 `bookProgressKey`，不得拿含本机路径的 `localFileKey` 代替。历史书签和阅读时长汇总仍有书名键。

## WebDAV 数据流

```text
AppWebDav.upConfig()
├── 校验 server/root URL
├── 初始化 bookProgress/books/background 目录
└── 设置 authorization/defaultBookWebDav

进度同步
├── 身份: 本地书内容 SHA-1；同名冲突的在线书使用 bookUrl SHA-256
├── 上传: AppWebDav.uploadBookProgress() -> bookProgress/v2-<key SHA-256>.json
├── 首次建立: v2 GET 返回 HTTP 404 -> 视为远端无记录 -> 上传本地有效位置
├── 旧版兼容: keyless 唯一本地书先验证 v2；无有效 v2 才回退 legacy，迁移完成后固定为 v2
└── 下载: AppWebDav.getBookProgress() / downloadAllBookProgress()

Web 阅读进度
├── 打开书架: 只读 Room，不触发 WebDAV
├── 点击书籍: POST /syncBookProgress -> 单书拉取 -> 只应用更靠前且范围有效的远端进度
├── 连续阅读: 浏览器固定 5 秒窗口 -> POST /saveBookProgress -> 先写 Room
├── WebDAV 上传: WebBookProgressUploadScheduler 固定 60 秒窗口，只上传最新 dirty 位置
├── 可见总进度: (durChapterIndex + 1) / 当前目录总章数 -> 百分比 + 当前章/总章
│   └── 搜索结果预览期间固定显示跳转前章节，确认保留当前位置后才切换
└── 切章/隐藏/离开: /saveBookProgress?flush=true；关闭页面用同一路径的 Beacon

Web 阅读时长
├── 进入章节: 浏览器启动章节计时并记录最后活跃时间
├── 滚动/点击/触摸/按键/恢复可见: 仅更新本地活跃状态，不发心跳
├── 任一活跃间隔超过 10 分钟: 本章保持作废，直到切换章节后重置
└── 切章: POST /saveReadTime（书名 + 经过时长）
    └── 手机端校验 5 秒至 24 小时 -> 以手机时间为结束点 -> 按自然日拆分写入 readRecord
```

规则:

- 不记录账号、密码、Authorization、URL query/fragment。
- 401 是服务端鉴权/路径问题，要和本地 `SecurityException` 分开记录。
- 恢复备份后的 `content://.../tree/...` 不能跨设备假设有效。
- Web 单书拉取、App 启动全量拉取和 Web 上传按书互斥；远端落后时不得覆盖 Room。
- 同名书的互斥、60 秒上传状态和 WebDAV 文件选择必须包含 `bookProgressKey`/`bookUrl`，不能继续按 `name + author` 合并。身份文件中的 key 必须与本地目标严格一致；有 key 后不回退旧文件。
- Room 84 及更旧记录的 key 为空。可读的 keyless 唯一本地书首次同步从精确 `bookUrl` 计算内容 key，先验证身份匹配且范围有效的 v2；仅在 v2 缺失、无效、身份错或越界时回退 legacy，再将可信远端与本地较新的有效位置写入 v2 后持久化 key；同名歧义书补 key 后绝不读 legacy。文件不可读时跳过同步，不能猜测旧进度。首次旧书架同步会产生一次顺序摘要读取，需留意大书架耗时。
- WebDAV 服务器的 404 响应可能没有 `Not Found` 短语或标准 XML 错误体；底层必须仅按 HTTP 状态将它归类为 `ObjectNotFoundException`，让上层把缺失 v2 当成可上传建立的正常状态。旧版只识别 legacy 文件，所有参与同步的设备需升级到支持 v2 的版本；不得为与旧版双向同步而重新读取无身份 legacy。
- 进度去重键不含时间戳；上传失败后不循环重试，只等待新位置、离开页面或重新打开书籍。
- Web 可见总进度是章节索引和目录长度的纯派生值，不新增 Room/WebDAV 字段，也不依赖章内位置、Web 页码、字体或视口；无目录时不显示，越界索引只用于安全钳制展示。
- 阅读时长不信任浏览器结束时间；恢复可见或超时后的首次交互必须先检查已经发生的空闲间隔，不能先刷新时间再判断。

## Web 全文搜索数据流

```text
BookContentSearch.vue -> /searchBookContent WebSocket
└── BookContentSearchService
    ├── isLocal && bookUrl 不是 webDav::
    │   ├── 扫描 Room 全部章节
    │   └── origin 为 webDav:: 时用禁用远程回源的副本读取手机原文件
    └── 在线书或 bookUrl 为 webDav:: 的远程文件
        ├── 固定一次章节缓存文件快照
        └── 只用 getCachedContent() 搜索命中缓存的章节
```

规则:

- `origin` 表示来源和同步关系，不代表正文当前存放位置；本地书上传 WebDAV 后 `origin` 会变成 `webDav::...`，`bookUrl` 仍是手机 URI/路径，必须继续按本地原文件搜索全部章节。
- 真正远程定位的 WebDAV 书以 `bookUrl` 的 `webDav::` 前缀识别，只允许搜索已有缓存；缓存快照后文件消失也不得调用通用 `getContent()` 回源。
- WebDAV 关联的本地文件搜索时要保留原书给 `ContentProcessor` 使用，但文件读取对象必须移除远程来源，防止本地授权失效或文件消失后由 `BaseFileBook` 自动下载。
- 搜索结果每批最多 500 条；`complete.hasMore=true` 时由浏览器原样带回 `nextCursor`，手机从章序和章内首条未返回命中继续。游标不保存服务端长期会话，章节/缓存快照变化导致游标失效时必须重新搜索。

## Web 前端资源边界

- `modules/web/src/` 是源码，`app/src/main/assets/web/` 是 APK 内实际加载内容。
- 修改 Web 运行时源码后，必须同步 assets，否则打包后不生效。
- 阅读页核心文件通常是 `modules/web/src/views/BookChapter.vue` 和 `modules/web/src/store/bookStore.ts`。
- 无限滚动追加章节不要走全局 loading mask。

网页传书:

```text
欢迎页 / 书架“网页传书”
└── /#/uploadBook -> UploadBook.vue
    ├── 选择或拖入多个受支持文件，按队列逐个上传
    └── XMLHttpRequest + FormData -> POST /addLocalBook
        └── BookController.addLocalBook()
            ├── FileBook.saveBookFile() 保存到手机书籍目录
            └── FileBook.importLocalFile() 解析并写入 Room 书架

旧地址 /uploadBook/index.html -> 只跳转到 /#/uploadBook
```

规则:

- `addLocalBook` 用 `ReturnData` 表达业务成功或失败，两种结果的 HTTP 状态都可能是 200；网页只有在 `isSuccess=true` 时才能显示“已导入手机书架”，失败必须展示 `errorMsg` 并允许重试。
- multipart 请求不得手写 `Content-Type`，否则缺少浏览器生成的 boundary，NanoHTTPD 无法解析 `fileName`/`fileData`。
- 网页可选格式必须与手机端 `AppPattern.bookFileRegex`/`archiveFileRegex` 一致：TXT、EPUB、UMD、PDF、MOBI、AZW3、AZW、CBZ，以及含受支持书籍的 ZIP、RAR、7Z。

## WebService 生命周期与通知数据流

```text
WebService.start()
├── Android 17 + targetSdk 37: 精确检查 ACCESS_LOCAL_NETWORK
│   ├── 未授权 -> WebServicePermissionActivity 用途说明 -> 系统权限请求
│   │   ├── 允许 -> 回到 WebService.start()
│   │   └── 拒绝/取消 -> 开关回退关闭；可由用户选择进入应用设置
│   └── Quick Settings Tile 缺权 -> startActivityAndCollapse(PendingIntent)
└── 已授权或 API 26-36 -> ContextCompat.startForegroundService()
    └── onCreate() / onStartCommand() / upWebServer() 再次检查精确权限
        ├── 注册 NetworkChangedListener、SAVE_CONTENT 观察和 30 分钟重启检查
        ├── restartGuard + isRestarting 防止并发重建
        ├── 启动 HttpServer / WebSocketServer
        └── 两个 server 都启动后，restartGuard 提交 isRun、Tile、hostAddress、启动时间与通知

正常刷新
├── 首次通知: ServiceCompat.startForeground(...DATA_SYNC)
└── 后续地址刷新: notificationManager.notify(NotificationId.WebService, ...)

缺权直接 FGS 启动
└── 最小前台通知完成系统握手 -> requestStop() 立即移除通知和端口

停止/拒权/失败/超时
└── requestStop() -> tearDown() -> stopSelf()
    ├── restartGuard 内先置 isStopping=true、isRun=false
    ├── isStopping 短路网络回调、serve、通知刷新和定时重启
    ├── 取消 restartChecker，注销网络监听，停止两个 server，释放锁
    └── finally: stopForeground(STOP_FOREGROUND_REMOVE)
        -> notificationManager.cancel(NotificationId.WebService)
```

规则:

- `tearDown()` 与 `upWebServer()` 的成功提交段必须共用 `restartGuard`；停机抢先时，后台刚启动的 server 也要立即关闭，不能重新写回 `isRun=true`。
- Android 17 且 targetSdk 37 时，所有 WebService 用户入口和服务端重建入口都必须精确检查 `ACCESS_LOCAL_NETWORK`；不得用同权限组的其他授权替代。API 26-36 直接通过，不弹这项权限。
- 专用权限 Activity 必须自持 Activity Result 状态，不依赖进程静态回调；Tile 在 Android 14+ 通过 `startActivityAndCollapse(PendingIntent)` 进入该 Activity。拒绝、取消或设置页返回仍缺权时必须写回关闭状态。
- 绕过 UI 直接启动 FGS 而缺权时，必须先用最小通知完成 foreground promotion，再走统一停机；在 `onCreate()` 里直接 `stopSelf()` 会触发 `ForegroundServiceDidNotStartInTimeException`。
- 清理通知只取消 `NotificationId.WebService`，不得使用 `cancelAll()` 影响缓存、下载或朗读通知。
- companion `stop()` 仍先取消同一通知 ID，兜底清理服务已不存在时的历史孤儿通知；内部停止、启动失败和 Android 16 `dataSync` 超时统一走 `requestStop()`。

## 离线缓存与导出数据流

```text
CacheActivity
├── CacheBook.start() -> CacheBookService
├── CacheProgressTracker 记录本次新增任务、已处理、失败和取消
├── 页面与前台通知复用同一进度快照
├── CacheCompletionGate 在用户取消或服务销毁时禁止完成通知
└── 自然完成通知 -> CacheActivity 的 TXT/EPUB 导出入口

ExportBookService
├── 普通本地书: 从原书文件读取章节
└── 在线书或 WebDAV 来源书
    ├── RequireComplete: 任一正文章未缓存即停止导出
    └── CachedOnly: 仅选择已落盘正文和卷标题
```

相关实现文件:

- `app/src/main/java/io/legado/app/ui/book/cache/CacheActivity.kt`
- `app/src/main/java/io/legado/app/model/CacheBook.kt`
- `app/src/main/java/io/legado/app/service/CacheBookService.kt`
- `app/src/main/java/io/legado/app/model/CacheProgressTracker.kt`（同时定义 `CacheCompletionGate`，当前没有独立的 `CacheCompletionGate.kt`）
- `app/src/main/java/io/legado/app/service/ExportBookService.kt`

规则:

- 缓存进度的分母是本次实际入队任务，不是书籍总章节覆盖率；重试不重复增加总数，已缓存章节和卷标题按已处理计入。
- 目录尚未加载时使用不确定进度，目录可用后再显示确定进度；失败和取消必须与已处理数分开保留。
- 只有自然完成才能保留可点击的完成通知；用户停止单书、停止全部或服务进入销毁时先关闭完成通知门闩，再取消下载协程和线程池任务。
- 在线书和 WebDAV 来源书导出正文必须走 `BookHelp.getCachedContent()`，缓存检查后文件又被删除时应终止并删除不完整输出，不能回退书源/WebDAV 联网或写入 `null`。
- “原始缓存正文”指书源规则已经解析并保存的正文，不是原网页 HTML；缓存页每次导出都显式选择原文或净化，不能通过修改全局默认值改变其他导出入口的既有行为。
- EPUB 只嵌入已经落盘的章节图片；在线封面仅允许命中 Glide 缓存，不为离线导出额外联网。
