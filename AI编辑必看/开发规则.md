## 编码规则

- 缩进 4 spaces；命名使用 Kotlin 常规 camelCase/PascalCase。
- 有 ViewModel 的 Activity 优先继承 `VMBaseActivity<Binding, ViewModel>`，无 ViewModel 可用 `BaseActivity<Binding>`；有 ViewModel 的 Fragment 使用 `VMBaseFragment<Binding, ViewModel>`，普通 Fragment/Dialog 使用 `BaseFragment()` / `BaseDialogFragment()`。
- View 使用 ViewBinding，不新增 `findViewById` 风格代码。
- 数据库访问走 `appDb.xxxDao()`；新增或修改的 DB 操作优先放协程/IO 线程。项目仍启用了 `allowMainThreadQueries()` 并保留少量遗留同步查询，不能把“全部已在协程”当成当前事实。
- 本地书数据库身份以 `localFileKey = SHA1(URI/路径 + 内容 SHA1)` 为准；`name`/`author` 索引只用于检索，不得恢复唯一约束，也不得用同文件名查询后改写另一记录的 `bookUrl`。持久化主键变更统一调用 `BookDao.relocate()`，并清空无法安全重算的过期身份键。
- 通用工具放 `utils/`；业务逻辑放对应模块，不在界面层堆 DB/网络细节。
- 兼容旧 API 时按 API level 分支，旧分支局部 `@Suppress("DEPRECATION")`。
- 不用 `GlobalScope` 承接普通业务协程。
- `values/strings.xml` 新增可翻译界面字符串时，同步维护 `values-vi`、`values-pt-rBR`、`values-ja-rJP`、`values-es-rES`、`values-zh`、`values-zh-rTW`、`values-zh-rHK`，并保持所有 `%1$d`、`%2$s` 等格式占位符一致。

## 构建验证

```bash
# 最小 Debug Kotlin 编译验证
scripts/check-debug.sh

# Debug APK
./gradlew :app:assembleDebug --no-daemon

# 提交前 Release/R8 编译验证（只证明编译/R8，不作为最终交付）
./gradlew :app:assembleRelease --no-daemon

# 最终提交且工作树干净后，生成并校验可直接安装的个人签名 Release APK
scripts/build-signed-release.sh

# Web 可复现安装、类型检查与生产构建
cd modules/web
pnpm install --frozen-lockfile
pnpm run test:read-time
pnpm run type-check
pnpm run build-only
cd ../..
cp modules/web/dist/index.html app/src/main/assets/web/index.html
cp modules/web/dist/favicon.ico app/src/main/assets/web/favicon.ico
cmp -s modules/web/dist/index.html app/src/main/assets/web/index.html
cmp -s modules/web/dist/favicon.ico app/src/main/assets/web/favicon.ico
scripts/check-web-assets-sync.sh
```

注意:

- Gradle 使用的 Android SDK 由 `local.properties` 指定；当前机器指向 `/home/liu/Android/Sdk`。仓库内 `.sdk/build-tools` 主要作为签名校验工具的优先查找位置，不等于 Gradle SDK。
- Gradle 下载/AGP/split APK 等细节看 `适配踩坑记录.md`。
- `scripts/build-signed-release.sh` 要求工作树干净，并只接受 `app/gradle.properties` 与 keystore 权限为 `400` 或 `600`（通常使用 `600`）；脚本校验固定个人证书、五个 APK、包名和版本，再把同批 APK/`.idsig`/metadata 原子同步到 `app/app/release/`。64 位安卓真机优先安装 `legado_arm64.apk`。
- KSP 当前版本为 `2.3.10`；修改数据库后统一运行 `scripts/check-debug.sh`（或更完整的变体编译/测试）触发当前 AGP/KSP 任务图，不在文档中依赖可能变化的单独任务名。
- 完整 `lintAppDebug` 当前仍有历史错误，不能只看任务退出码；新增资源后应对比修改前后的错误数和具体资源名，确保没有引入新的 `MissingTranslation`。
- `modules/web/pnpm-lock.yaml` 是 Web 构建的受控依赖快照；安装必须使用 `--frozen-lockfile`，依赖变更时同步提交 lockfile。
- Web 构建启用 `vite-plugin-singlefile`，业务 JS/CSS 全部内联进 `dist/index.html`；独立产物只有 `index.html` 和 `favicon.ico`，因此只需同步这两个文件。
- Web 阅读时长状态机有独立的无浏览器测试 `pnpm run test:read-time`；修改空闲阈值、切章提交或活动事件时必须先跑该测试，再执行类型检查和生产构建。
- 本地 `pnpm build`/`build-only` 不会自动复制 assets（`scripts/sync.js` 仅在 GitHub Actions 环境复制）。生产构建后必须手动同步 `index.html` 和 `favicon.ico`，并用 `cmp -s` 确认 `modules/web/dist/` 与 `app/src/main/assets/web/` 字节一致。`scripts/check-web-assets-sync.sh` 是暂存区拦截器，不能单独替代类型检查和生产构建。
- `./gradlew :app:assembleRelease` 仅用于提交前 Release/R8 编译验证；最终交付不得直接取其产物，必须在最终提交且工作树干净后运行 `scripts/build-signed-release.sh` 完成证书、包名、版本、五个 APK 和 v4 `.idsig` 校验。

## 文档维护

- 兼容性/API/构建/运行时适配问题写入 `适配踩坑记录.md`。
- 新功能设计、交互、性能和回归测试先更新 `新功能踩坑记录.md` 索引，再写入对应的阅读页、Web 服务或基础设施分卷。
- `适配踩坑记录.md` 最多保留 15 条；满 15 条后整体改名归档到 `文档归档/` 并重新开新文件记录，不再来回挪动单条。
- 主入口 `../AI编辑必看架构图.md` 只保留路由和红线；详细内容写入本目录子文件。
- `app/src/main/assets/updateLog.md` 顶部追加 `**YYYY/MM/DD**` 和本次修改摘要；只直接展示最近 5 个日期，新增日期后把第 6 个及更旧日志按时间倒序收入文件末尾唯一的 `<details><summary>more</summary>` 折叠区。每个日期最多 2 句话，只保留用户需要知道的功能、修复或兼容变化。更新日志不是完整改动清单；依赖升级、构建脚本、验证过程、内部重构和实现细节默认不写。

每轮代码或文档结构修改后的同步清单:

1. 对照真实代码、Manifest、版本目录和脚本，更新受影响的架构/适配/新功能文档，不只改时间戳。
2. 子文档结论或索引变化时，同步刷新 `../AI编辑必看架构图.md`；本机 `AGENTS.md` 存在时也同步其摘要和 `Last updated`。
3. 时间敏感结论保留独立的记录/验证日期；未执行的联网、浏览器或真机验证必须明确写“待验证”，不得用文档复核日期覆盖。
4. 检查各文件顶部复核日期与末尾 `Last updated` 自洽，并运行 `git diff --check`；Web 相关修改再执行类型检查、生产构建和 assets 字节比较。
